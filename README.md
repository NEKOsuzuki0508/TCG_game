# 売ってないTCG — 公式最新版＋非公式1000番台 対戦サイト

`index.html` をブラウザで開けば使用できます。外部ライブラリなし、オフライン動作、AI対戦・同じ端末での2人対戦に対応します。

## カードデータの出典と優先順位

- **公式カード No.1〜91：** プロジェクトの新版 `基本ルールとカードリスト2.txt` の内容を採用。標準収録済みなので、登録ボタンは不要です。
- **No.92：** 新版ソースには番号だけがあり、名前やステータスがないため収録していません。情報確定後に画面から追加できます。
- **非公式 No.1000〜1035：** 従来 No.88〜123 のビビッドアーミーを参考にした独立設計36人。能力とバランスは維持し、番号と出典区分だけ変更しました。
- **新規の非公式カード：** フォームを開くと No.1036以降が自動採番されます。
- **新規の公式カード：** No.92以降の番号と「公式カード」の出典区分を指定し、カード管理から登録できます。

公式91人の持ち技259個は名称、説明、コスト表記を保持。単純な攻撃などのみ自動処理し、特殊技は原文を提示して手動裁定になります。特に `リーズ` の「りようほう」「かいとり」は元資料の可変コスト表記を表示し、自動のMP支払処理はできません。ルールに従って対戦者がコストを確認してください。

## 旧版からのデータ引き継ぎ

同じブラウザで旧版を利用していた場合、初回起動時に次を自動処理します。

1. 既存の編成にある旧・非公式 No.88〜123 を No.1000〜1035 に置換します。
2. 保存されていた旧公式 No.1〜91 のユーザー登録コピーを整理し、新版を優先します。
3. 移行前のデータをブラウザ内のバックアップ用キーにコピーします（保存容量によりバックアップできない場合があります）。
4. 進行途中の対戦データも旧・非公式番号を可能な範囲で移行します。

旧ブラウザデータと現在のブラウザデータは共通の保存領域にあります。**重要なカードのJSONバックアップは、更新前に保存することを推奨します。** ブラウザの保存データを消すと、追加カードも消えることがあります。

## ゲームの遊び方

1. `index.html` を開き、「AI対戦」か「2人対戦」を選択します。
2. 1チーム6人を編成し、ゲーム開始後、ターンごとに3人までを出します。
3. 各キャラクターの攻撃・持ち技を手札のMPカードや属性カードで発動します。
4. 未自動化の技は「手動裁定」パネルからHP・ステータス・状態異常などを反映します。
5. 「カード管理」で追加カードを登録・編集・JSON保存できます。

## 制約

- インターネット経由の別端末間対戦には非対応です。
- 全公式カードの複雑な技や特殊コストを完全自動処理するものではありません。
- 旧版で同じカードNo.を別用途に独自登録していた場合、JSONバックアップから照合してください。

## ダメージ計算の修正
通常攻撃・攻撃技は威力が相手のぼうぎょ値以下の場合、最終的にも確定10ダメージとなります。威力がぼうぎょ値を超える場合は差額です。今回の修正裁定として、追加の軽甲・重甲・「被ダメージ−30」等の数値軽減があっても、確定10の場合はHPを最低10減らします。ただし「まほうの甲冑」のように攻撃自体を完全に防ぐ効果は有効です。発動時は戦闘ログに最低ダメージと確定10の保証処理が表示されます。

## 対戦中の「新規対戦」ボタン

対戦が始まった後も、出場者選択・行動中・2人対戦の端末交代・勝敗画面で、画面上部に「＋ 新規対戦」ボタンを表示します。スマートフォンでも表示し、スクロール中は上部に固定されます。進行中に押すと「進行中の対戦を終了し、新規対戦を作成しますか？」と確認し、承認時だけ対戦データをリセットして編成・モード選択画面に戻ります。登録カードや保存済みの編成は維持します。

## 追加機能：自由な60枚デッキ編成

上部ナビゲーションの「デッキ編成」から、青チームと赤（AI）チームそれぞれの**山札60枚**を作成できます。対戦開始画面の各チーム欄にある「デッキ編成 →」からも開けます。

- **MPカード：** 1MP・2MP・3MPの枚数を変更できます。保存時に `1MP ≧ 2MP ≧ 3MP` の条件を検査します。
- **特殊コストカード：** ほのお・葉っぱ・水・やみ・風・どく・ひかりの7種類から自由に選べます。選んだ6人の技に必要な種類が0枚の場合は注意を表示します。
- **補助カード：** 新版公式ルール記載の11種類から選べます。「市販結界装置」も選択でき、次に受ける攻撃の無効化（やみ属性の技は半減）に簡易対応しています。
- **枚数操作：** 各カードの `− / ＋` ボタンまたは数値入力。合計が60枚でなく、あるいはMPの不等式に違反すると保存できません。
- **保存と適用：** 「この60枚を保存する」を押すとブラウザに保存し、**次の新規対戦から**選んだ構成をシャッフルして山札に使用します。進行中の対戦データは書き換えません。
- **プリセットとコピー：** 「おすすめ配分」で現チーム向けの既定配分を呼び出し、「もう一方のチームへコピー」で反対側に同じ60枚を保存できます。「自動編成に戻す」で従来の自動生成に戻せます。
- **バックアップ：** 青・赤両方のカスタムデッキをJSONで保存・復元できます。1チーム分の60枚のJSON配列も読み込めます。

保存キーは `tcg_vivid_decks_v1` です。旧版の対戦状態 (`tcg_vivid_state_v1`) およびキャラクター編成の保存データとは独立しており、従来の対戦データを移行できます。カードの枚数上限や種類ごとの投入上限は元のルールに明記されていないため、新たな投入上限は設定していません。

### 既知の簡易裁定

対戦画面では一部の公式カードの複雑な効果が手動処理です。既存の仕様は維持しています。山札がなくなった際の捨て札のシャッフル再利用は従来どおりです。デッキのカスタマイズは端末のブラウザ内に保存されるため、別のブラウザや端末へ引き継ぐ場合はJSON書き出しを使用してください。


## 追加機能：自由編成の名前付き保存・マイ編成

上部ナビゲーションの「マイ編成」、または対戦準備画面の「この6人に名前を付ける」から利用します。

1. 対戦準備画面の「キャラクター6人を編集」で、公式・非公式・自作カードから自由に6人を選択します。
2. 「マイ編成」を開き、青チーム/赤チームを選択して編成名（1〜60文字）を入力します。
3. 必要なら「現在の60枚デッキもセットで保存」をチェックし、名前付きで保存します。
4. 保存した編成は一覧から青/赤どちらにも呼び出せます。編集・名称変更・削除が可能です。
5. 全編成をJSONとしてバックアップしたり、別端末でJSONを読み込んだりできます。

最大200編成をブラウザの `localStorage`（キー `tcg_vivid_named_formations_v1`）に保存。元の6編成とカード127人は維持。作成した編成は**次の対戦開始時**から使用され、すでに進行中の対戦は書き換えません。

専用デッキを「一緒に保存」にチェックした場合は、選んだサイドの60枚デッキをスナップショットとして保存。保存時に自動デッキだった場合もその状態が記録されます。未チェックの場合は呼出時の既存デッキ設定を変更しません。

独自カードも編成に含められますが、編成保存データに独自カードのカード全文は含みません。別端末で未登録カードを使用する場合、まず「カード管理」のJSONでそのカードデータを移してください。

## GitHubクラウド同期（手動バックアップ）

本サイトは静的HTMLのため、GitHub Pagesへのサイト公開だけでブラウザの保存データがクラウド共有されるわけではありません。新設した「マイ編成」画面では、GitHub REST APIの [Create or update file contents](https://docs.github.com/en/rest/repos/contents#create-or-update-file-contents) を利用して、**選択したリポジトリ内のJSONファイルに編成一覧を保存・復元**します。

### サイトの公開方法

1. GitHubにサイト公開用リポジトリを作成し、`index.html`（単一ファイル版）をリポジトリ直下にアップロードします。ZIPに含まれる他のソースファイルも任意で追加できます。
2. GitHubのリポジトリ設定から Pages の公開元を設定し、生成された `https://...github.io/.../` のURLでサイトを開きます。
3. 「マイ編成」から所有者・リポジトリ名・ブランチ（例：`main`）・保存先パス（例：`data/tcg-formations.json`）を設定します。保存先はサイト公開用リポジトリと別でもかまいません。
4. GitHubの個人アクセストークンを使用する場合は、可能なら**対象リポジトリ1つだけ**を指定した fine-grained token を使用し、`Contents: Read and write` だけを付けます。GitHubではトークンをパスワードと同じように管理してください。
5. 読込ボタンは公開リポジトリであればトークンなしでも利用できる場合があります。非公開リポジトリや書込時は、サイト画面にトークンを入力して操作します。**トークンはこのHTMLにもブラウザのlocalStorageにも保存されません。チャットにも貼らないでください。**

### 重要な操作仕様

- **初回のクラウド読込：** すでにGitHub側に保存ファイルがある場合、先に「クラウドから読み込む」を押してください。ローカルにある編成は保持し、同じ保存IDは更新日時が新しい方を優先して統合します。
- **クラウドへ保存：** GitHub上のSHAを確認してからJSONを書き込みます。ほかの端末が先に更新していた場合には書込みを拒否するため、データの不意な上書きを防ぎます。
- **削除：** ローカルで編成を削除してもGitHub側に即反映されません。前回読込時からGitHubに更新がなければ、次の「GitHubへ保存する」で反映します。
- **通信：** クラウド同期はHTTPSで開いたページのみ対応。ローカルのHTMLファイルからは利用せず、JSONバックアップを使ってください。
- **公開範囲：** 公開リポジトリ内のJSONは誰でも読めます。自分だけが使う場合は、データ用に別の非公開リポジトリを用いることもできます。
- **保存対象：** 名前付きの6人編成と、編成に紐付けた60枚のコスト・補助カード構成です。**対戦途中の戦況、カード管理に登録した独自カードの全文、ブラウザにある2チームの編成設定はクラウドに保存されません。** 必要な場合はそれぞれJSONでバックアップしてください。

GitHubの本番アカウントへの書込みは、ユーザーのリポジトリと認証が必要なため未実施です。通信のリクエスト・レスポンスはモックAPIで、ブラウザのPC/スマートフォン表示と合わせてテストしています。

## 追加修正：対戦効果・使用回数・コスト表示

- **みがわり：** 発動した次のターンは、そのキャラクターを出場させる必要があります。敵からの通常攻撃・技・攻撃由来の直接ダメージ・拡散攻撃は、みがわり中のキャラクターに集約されます。
- **プレイヤーが発動を選ぶとくせい：** 条件を満たすとくせいは、配置選択画面または行動画面に発動ボタンを表示します。効果が複雑で自動化できないものは、宣言後に手動裁定パネルで処理します。「こまめのおこぼれ」「いそぎのようじ」は簡易自動処理し、「きせきのきずな」は味方が瀕死になる見込みの攻撃を受ける前に発動確認を出します。
- **死亡時効果：** 「やみへのさそい」は、同じ技を持つ敵がフィールドにいる場合、ランダムな1人を道連れにします。その他の死亡時効果は、死亡時効果の手動裁定パネルを表示します。
- **属性コスト表示：** `costText` がある技はその表記を優先し、`special` の属性カードを重複表示しません。`costText` がない追加カードは必要な属性カードを補って表示します。
- **ゲーム中の使用回数制限：** 技の説明にある「バトル中に1回しか使えない」「1バトルにつき最大2こまで」などを読み取り、使用回数を対戦データに保存します。使用上限に達した技は選択できません。プレイヤーが選ぶ一度きりのとくせいも使用済み状態を保持します。

複雑な公式効果は引き続き手動裁定が必要な場合があります。`python test_battle_fixes.py` で、みがわり、死亡時効果、きせきのきずな、1回限定技、属性コスト表示を確認できます。
